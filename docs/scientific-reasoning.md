# Scientific Reasoning Council 설계

## 역할과 실행 경계

기존 연구 루프에서 가설 연구자는 Abduction Agent, 비판 검토자는 Falsification Agent 책임을 맡는다. Toulmin 구조화, 변증법 진행, 실험 엄격성 감사, 연구 프로그램 평가에는 별도 역할과 세션 키를 부여한다. Director는 평소와 같이 다음 작업을 제안한다. Control Plane은 권한, 선행 작업 및 필수 검증을 결정론적으로 검사한다. GJC와 Router는 공통 AgentRuntime을 사용하고 기존 GJC 설치 버전은 변경하지 않는다.

| 방법론 | 기본 개념과 Lab의 적용 |
| --- | --- |
| Peirce | 관측을 설명할 경쟁 설명을 제안하는 가추. PoC에서는 센서 신호, 시차 및 방향으로 구별되는 가설과 예상 관측을 받는다. |

| Dung | 추상 공격 관계와 공격자에 대한 방어로 grounded extension을 계산한다. 결과는 특정 공격 그래프 안에서의 수용 가능성이다. |

| Popper | 실험 전에 반증 조건을 지정한다. PoC에서는 데이터 분리, 효과 방향, 비교 임곗값과 최소 그룹 크기를 고정한다. |

| Lakatos | 가설 계열의 새 예측과 독립 확인을 비교한다. 초기 기준과 관찰 후 수정, 검증된 신규 예측을 별도로 집계한다. |

| Duhem–Quine | 실패가 주가설, 보조 가정, 측정 중 어디에서 비롯됐는지 구분한다. 진단 근거가 부족한 실패는 보류 가능한 판단으로 기록한다. |

## Phase A–C의 계약

`packages/scientific-reasoning`은 Agent 산출물의 스키마, 토론 단계, 그래프 및 검증을 정의한다. SQLite는 근거가 있는 다형 노드·엣지, 작성 역할, 기록 시각, 검증 상태를 Run과 산출 작업에 묶는다. `crates/logic-engine`은 설치된 연구 커널의 실행 인터페이스를 통해 공격 그래프와 제한된 기호 추론을 검사한다. 승인된 Rust 빌드가 없는 로컬 목업은 동일 의미의 TypeScript 규칙과 구현 표식을 사용한다.

형식 검증은 명시적 부호 명제와 사실·modus ponens에 한정한다. 기호 추론 성공과 자연어 정식화 확인을 분리한다. LLM이 제출한 정식화에는 독립 확인 표식을 자동 부여하지 않는다. 중복 출처는 스냅샷별로 묶으며, 서로 다른 출처 두 개를 갖는 것만으로 양쪽의 독립성을 단정하지 않는다. Dung 결과, Gate 결과, LLM 설명 및 경험적 결과를 서로 다른 필드로 기록한다.

기존 Run은 저장 당시 추론 방식으로 읽고 재개한다. 새로운 Run에 Council 구성을 저장한다. 새 검증이 정체되거나 필수 조건이 부족하면 합의나 관찰 위험차만으로 가설을 검증 완료 처리하지 않는다. 오류 근거는 Research Memory와 별도 저장소에 기록하며, 평가되지 않은 Harness를 활성화하지 않는다.

## 현재 검증 결과와 구현 범위

Windows의 합성 제조 PoC에서 가설 3개, 완료 작업 25개, 그래프 노드 29개와 관계 30개를 기록했다. 실제 Rust 로직 엔진을 사용했고, 세 가지 정식화의 기호 도출은 통과했다. 자연어 주장과 정식화의 대응 관계는 독립적으로 확인되지 않아 Gate B는 판단을 보류했다. 한 개의 개발 스냅샷이 제공됐고 측정 신뢰도 및 사전 검정력 근거가 부족하여 Gate D와 E도 판단을 보류했다.

별도 계산 경로로 보류 배치의 위험차를 재현했다. H1의 관찰 위험차는 `+24.2372%p`로 사전 임곗값을 충족했다. H2와 H3는 임곗값을 충족하지 못했다. 최종 연구 및 경험적 판정은 `INCONCLUSIVE`다. 초기 가설 계열은 `BASELINE`으로 저장했다.

Rust 테스트 4건, Node 테스트 26건과 엄격 TypeScript 검사를 통과했다. Node 테스트는 TypeScript 기본 경로와 Rust 실행 파일을 지정한 경로에서 각각 통과했다. Chromium에서 새 Run의 과학 검증 Gates, 저장된 논증 그래프, 연구 프로그램 평가, SIM 표시를 확인했다. 사내 Router/GJC의 실호출은 미실행이며 Router 호환 경로는 로컬 HTTP 목업으로 검증했다.

이번 변경은 Phase A–C의 스키마, 토론 및 형식 검사에 초점을 두고, 반증 계획 감사와 프로그램 판정의 기본 규칙을 연결한다. 전향적으로 검증된 검정력 모델, 실데이터 인과 식별 및 베이지안 검증, ASPIC+ 확장 의미론, 실제 Harness 후보 변경과 독립 승격 평가는 별도 구현·검증 범위다. 반복 오류는 SIM에 기록하며, 여러 Run에 걸쳐 같은 유형이 발생하면 허용 영역의 후보 과제를 생성하고 `PENDING_INDEPENDENT_EVALUATION`을 부여한다.
